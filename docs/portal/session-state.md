# Portal session state

Inventory of the session values the Portal reads and writes, where they are set and when they are cleared.

## Ownership

| Owner                            | State                                                                                                                                                                  |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Library-managed                  | Session ID, cookie and store. The cookie name is `portal` (`PortalService.otherSessionOptions`). `express-session` and the core service own the rest.                  |
| Portal-owned                     | Login and authentication fields, `visits`.                                                                                                                             |
| Shared library, Portal-triggered | `forms` (`@planning-inspectorate/dynamic-forms`), `fileUploader`, `errors`, `errorSummary`, `hasTempDocuments` (`packages/lib/forms/custom-components/file-uploader`). |
| Portal-owned, feature-specific   | `editingFromCheckAnswers` (Gateway 2 and 3).                                                                                                                           |

Typing: [session.d.ts](../../apps/portal/src/session.d.ts) declares only `visits` and an `[key: string]: any` index signature. Other fields are typed locally (`Gateway2Session`, `Gateway3Request`, `FileUploaderSession`) or accessed untyped.

`/logout` calls `req.session.destroy()`, which removes every field below. No field is cleared individually on logout.

## Login and authentication

| Field                | Purpose                                                                                                                                             | Set by                                                                                                           | Cleared or reset                                                                                                                                                    |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `email`              | Email in the current sign-in attempt, used by the OTP pages and new-code request.                                                                   | `buildSubmitEmailPage` (`views/login/controller.ts`): valid email, including unrecognised and locked-out emails. | Deleted when the email page renders (`buildEnterEmailPage`) and after successful OTP verification or bypass (`buildSubmitOtpPage`). Kept after failed OTP attempts. |
| `isAuthenticated`    | Authentication flag. Read by `checkIsAuthenticated` and `exposeAuthToViews` (`auth/guards.ts`).                                                     | `buildSubmitOtpPage` after successful OTP verification or bypass.                                                | Session destroy only.                                                                                                                                               |
| `authenticatedEmail` | Authenticated user's email. Read by the landing page to load plans and by `checkCaseOwnership` to authorise `/manage-local-plans/:planReference/*`. | `buildSubmitOtpPage` after successful OTP verification or bypass.                                                | Session destroy only.                                                                                                                                               |
| `showNewCodeMessage` | One-time "we've sent a code" banner on the OTP page.                                                                                                | `buildRequestNewCode` after a new code is sent.                                                                  | Read and deleted by `buildEnterOtpPage`. Not consumed if that page returns 404 (no `email`).                                                                        |
| `caseReference`      | Set to the user's email by `buildRequestNewCode`. No Portal code reads it.                                                                          | `buildRequestNewCode` (`views/login/controller.ts`).                                                             | Session destroy only. Purpose unclear: it looks like a leftover.                                                                                                    |

## Home page

| Field    | Purpose                | Set by                                                                      | Cleared or reset                    |
| -------- | ---------------------- | --------------------------------------------------------------------------- | ----------------------------------- |
| `visits` | Example visit counter. | `buildHomePage` (`views/home/controller.ts`) increments it on each request. | Session destroy only. Example code. |

## Journey answers (Gateway 2 and Gateway 3)

| Field                     | Purpose                                                                                                                                                                   | Set by                                                                                                                                                  | Cleared or reset                                                                                                                                                                                                                                                                             |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `forms`                   | Dynamic Forms answers. Case-scoped routes use `forms[planReference][journeyId][fieldName]`, so plans are isolated by reference. Non-scoped routes use `forms[journeyId]`. | `buildSaveDataToSession` (question POSTs) and `syncGateway2UploadAnswer` / `syncGateway3UploadAnswer` (file answers).                                   | Gateway 2: `buildSaveController` (`gateway-2-submission/save.ts`) calls `clearDataFromSession` for that plan's journey after submission. Gateway 3: no clear found. The shared upload **delete** controller deletes the whole `forms` object (all plans and journeys) on every file removal. |
| `fileUploader`            | Uploaded files per upload question: `fileUploader[sessionKey].uploadedFiles`. Case-scoped keys are `<planReference>:<fieldName>`.                                         | Shared upload and delete controllers; Gateway 2 and 3 populate it from persisted documents when a question page loads (`setFileUploaderUploadedFiles`). | Replaced per key on upload and delete. No whole-field clear found, including after submission.                                                                                                                                                                                               |
| `editingFromCheckAnswers` | Return to the check-your-answers page after saving a question.                                                                                                            | `setAsEditingFromCya`, on the Gateway 2 and 3 submission landing and check-your-answers GET routes.                                                     | Not cleared. Read by `redirectAfterCyaEdit`.                                                                                                                                                                                                                                                 |
| `errors`, `errorSummary`  | Upload validation messages (for example the file-size error) shown on the next page load.                                                                                 | Shared upload controller; `handleMulterFileSizeError` (Gateway 2 and 3); the Gateway 3 resubmission size error.                                         | Deleted by a successful upload, by `fileUploaderQuestionMiddleware` on question GET, and by the Gateway 3 resubmission upload page.                                                                                                                                                          |
| `hasTempDocuments`        | Tracks uploads that haven't been saved, for temporary-document cleanup. Only the Manage app reads it (`apps/manage/src/app/router.ts`).                                   | Shared upload controller.                                                                                                                               | The Portal never clears it. Reaches Portal sessions through the shared controller.                                                                                                                                                                                                           |
