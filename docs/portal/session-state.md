# Portal session state

This inventory describes current behavior, not an intended lifecycle. Portal-owned fields are declared in [session.d.ts](../../apps/portal/src/session.d.ts); the index signature remains for library-managed state.

## Ownership and storage

| Owner                                 | State                                                                                                                                                                |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Session infrastructure                | Session ID, cookie and store. Portal uses the `portal` cookie name and the `portal:` Redis prefix. The core service and `express-session` manage storage and expiry. |
| Portal                                | Login and authentication fields, `visits`, and `editingFromCheckAnswers`.                                                                                            |
| Shared libraries, triggered by Portal | Dynamic Forms `forms`; file uploader `fileUploader`, `errors`, `errorSummary` and `hasTempDocuments`. Portal also updates some of this state.                        |

`/logout` calls `req.session.destroy()` and redirects to `/login` in its callback. The store removes the session on successful destruction; the current callback does not handle a destruction error.

## Login and authentication

The [authentication session helpers](../../apps/portal/src/app/session/auth-session.ts) group these mutations. The login controller calls them at the same points as the previous direct mutations.

| Field                | Purpose                                                                     | Set or updated                                                                                                   | Cleared or reset                                                                                                                                                                                                              |
| -------------------- | --------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `email`              | Email for the current sign-in attempt, OTP pages and resend request.        | Valid, recognised email in `buildSubmitEmailPage`, including when the account is locked out.                     | Deleted on the email page GET, when the submitted email is unrecognised, when OTP verification finds the email no longer associated with a case, and on successful verification or bypass. Retained after other OTP failures. |
| `isAuthenticated`    | Authentication flag read by the authentication guards and exposed to views. | Set to `true` after successful OTP verification or bypass.                                                       | Session destruction.                                                                                                                                                                                                          |
| `authenticatedEmail` | Authenticated email used to load plans and check case ownership.            | Set after successful OTP verification or bypass.                                                                 | Session destruction.                                                                                                                                                                                                          |
| `showNewCodeMessage` | One-time banner on the OTP page.                                            | Set after the new-code notification call returns, including when Notify is unconfigured and the call is skipped. | Consumed and deleted on the OTP page GET. A request without `email` returns 404 before consuming it.                                                                                                                          |
| `caseReference`      | Currently set to the email, despite its name; no Portal reader was found.   | Set with `showNewCodeMessage`.                                                                                   | Session destruction. Do not remove without confirming external dependencies.                                                                                                                                                  |

## Journey and upload state

The [submission session helper](../../apps/portal/src/app/session/submission-session.ts) marks check-answers editing. Dynamic Forms and the shared uploader own their respective state formats; Portal's feature-specific controllers also populate them.

| Field                     | Purpose                                                                                                                                                                                 | Set or updated                                                                                                                                                                                                                                                                                        | Cleared or reset                                                                                                                                                                                                                                                                                                                        |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `forms`                   | Dynamic Forms answers. Case-scoped answers use `forms[planReference][journeyId][fieldName]`; Gateway 2 also supports unscoped `forms[journeyId]`.                                       | Dynamic Forms saves question answers. Gateway 2, Gateway 3 and examination controllers synchronize upload answers.                                                                                                                                                                                    | Gateway 2's save controller clears its journey, scoped by plan when applicable, before redirecting case-scoped requests to the declaration page. No equivalent clear was found for Gateway 3 or examination. The shared uploader's delete controller deletes the entire `forms` field, affecting all cases and journeys in the session. |
| `fileUploader`            | Uploaded files indexed by upload question's session key.                                                                                                                                | Shared upload/delete controllers and Portal controllers loading persisted documents. Gateway 2 and 3 case keys use `<planReference>:<fieldName>`; examination uses `<planReference>:<journeyId>:<fieldName>`; Gateway 3 resubmission uses `<planReference>:resubmissionDocuments:<submissionNumber>`. | Updated per key on upload or deletion; no whole-field clear was found after submission.                                                                                                                                                                                                                                                 |
| `editingFromCheckAnswers` | Gateway 2 and 3 use this flag when deciding whether to return to check answers after editing. Examination also sets it, although its question save redirects to check answers directly. | Set on the relevant Gateway 2, Gateway 3 and examination landing-page routes.                                                                                                                                                                                                                         | No individual clear found; session destruction removes it. The flag is not case- or journey-scoped.                                                                                                                                                                                                                                     |
| `errors`, `errorSummary`  | Upload validation messages displayed on a subsequent request.                                                                                                                           | Shared upload controller and Portal's Gateway 2, Gateway 3, Gateway 3 resubmission and examination file-size handlers.                                                                                                                                                                                | Cleared after successful upload and when the shared question middleware consumes them; the Gateway 3 resubmission upload page also clears them.                                                                                                                                                                                         |
| `hasTempDocuments`        | Shared uploader's tracking of temporary uploads.                                                                                                                                        | Shared upload controller. Manage reads it for cleanup; no Portal reader was found.                                                                                                                                                                                                                    | No Portal clear found; session destruction removes it.                                                                                                                                                                                                                                                                                  |
